# 18C — 我的房間、金鑰體驗、獨立建房與加密告知

- 狀態：規劃中，尚未實作。2026-09-23 由原 18D §2–§3（房間列表、金鑰體驗）與
  原 19（獨立建房 UX、全產品加密告知）合併；兩者的資料模型與授權部分已移入
  [18B](18b-collaboration-authority-reset.md)。
- 前置：[18B](18b-collaboration-authority-reset.md)（DO 授權權威、可選 scene 關聯、生命週期登記、
  儲存屏障、完整初始化後端與可靠列表投影）與 [18A](18a-collaboration-storage-ux.md)（儲存 UX 與本機快取邊界）。
- 目的：讓使用者找得回自己的房間、換裝置時得到誠實的說明、不必先建立未加密的個人場景就能開始加密共編，
  並在整個產品裡分得清楚哪些內容有 E2EE。
- 本文件描述目標，不代表現況。

## 0. 為什麼這些放在一起、而且放在 18B 之後

原 18D 與原 19 被拆開的理由是遷移排序（「退休流程必須早於 18C 的 P3 逐房間切換」）。
[18B](18b-collaboration-authority-reset.md) 取消了逐房間切換，那條排序限制消失，
留下來的是一個單純得多的分界：

- **18B 是授權權威與資料模型**，做完之後房間不再需要 scene、不再有到期時間、撤權在 DO 本地原子完成。
- **本計畫交付使用者操作流程**：列表 UI、金鑰提示、瀏覽器加密與建房流程、文案。
  初始化狀態機、owner 初始化 API、可靠列表投影與查詢 schema 全部由 18B §4.2.1 先交付，
  不等到這裡才補後端或修改 ready 的定義。

放在 18B 之後不是階段性妥協，是因為這裡每一個畫面都要顯示 18B 才存在的狀態（可選 scene 的房間、
沒有到期時間的房間、`enforced`／`pending`／`projectionPending` 三種結果）。

驗證分層沿用 [18B §0.4](18b-collaboration-authority-reset.md)：列表投影的排序／去重／不倒退、缺鑰路徑、
初始化失敗與重試，使用 PGlite、Worker runtime 與本機多連線 Postgres（L2″）驗證；**只有 production 的實際操作驗收與多裝置
情境需要等 Neon 額度恢復**（§7 標 `[L3]`）。

**儲存契約的唯一定義處是 [18A](18a-collaboration-storage-ux.md)。** 模式與目的地對照表、房間保存狀態、
快捷鍵協調、另存／下載／更新原稿三個入口，以及本機快取隔離與恢復規則，全部以 18A §3、§4 為準；
本計畫不重述、也不重新定義它們，避免同一份契約存在兩個會各自漂移的副本。

## 1. 範圍

本次納入：

- 串接 18B 已完成的房間列表查詢／可靠投影，實作分頁與同步狀態 UI。
- 本機金鑰記憶、缺鑰體驗與跨裝置的誠實說明。
- 未儲存畫布直接建立獨立房間的流程、初始內容加密上傳、失敗恢復與重進。
- 全產品的加密狀態標示、不打斷操作的個人雲端存檔說明、發布／匯出告知。
- production 的實際使用流程驗收與多語系／無障礙文案。

本次不做：

- 跨裝置自動金鑰恢復、使用者金鑰 envelope、伺服器持有解密金鑰。
- 即時「最後編輯」排序或為此新增 heartbeat。
- 個人雲端場景 E2EE、匿名共編、自動輪替房間金鑰。
- 阻止已取得明文的成員另存內容。
- 重新定義 18A 的儲存入口語意。

## 2. 我的房間列表

Neon 保留使用者 → roomId 的查詢投影，包括 owner／member、可展示的房間標籤、狀態與來源版本，提供分頁
列表。**列表中的角色只是顯示提示**；進房間與內容 API 都重新由 Room DO 判斷。

- 可靠同步與條件式 upsert／tombstone 須先由 18B §4.2.1、§6 交付。本計畫驗證 UI 在重送、
  亂序與刪除晚到時呈現正確，不再建立第二套同步 writer。
- **列表查詢以 roomId 與 subject 為依據，不得 inner join scene**——獨立房間沒有 scene，join 會讓它們
  整批消失。
- 房間名稱須定義是否為可見 metadata，不從加密內容推導縮圖或名稱。預設房間標籤不從畫布內容推導。
- 不將每筆筆畫或 presence 同步到列表。首版不做即時「最後編輯」排序；若需要，使用已有快照儲存時間，
  不為此新增 heartbeat。
- 列表允許短暫過期；建立／加入頁可用操作回應顯示同步中，不能因暫未出現在列表而認定加入失敗
  （這正是 18B 的 `projectionPending`）。
- 「我的房間」與現有個人白板列表必須分清楚，不把兩種存檔混為一談。

## 3. 金鑰體驗

**首版金鑰策略：**延續完整分享連結的 fragment。取得正確金鑰並經 key-check 後，可在本機瀏覽器按
userId／roomId 保存房間秘密，登出或移除本機記錄時清理。不把秘密、完整分享連結傳入 Neon、DO、日誌或分析。

- 同一瀏覽器保有金鑰：從列表進入可恢復解密。
- 新裝置／清除瀏覽器資料：列表仍看得到房間，但提示提供完整邀請連結；**不得顯示空白畫布並覆寫原快照**。
- 登入本身不能恢復 E2EE 金鑰。本機記憶改善便利性，但增加該瀏覽器中秘密保存時間；XSS／同源程式可存取的
  風險仍存在。
- 若未來要求跨裝置一鍵進房，再獨立設計使用者金鑰與加密 key envelope；不以 server 明文保存 root key
  作捷徑。

本機金鑰記憶與 [18A](18a-collaboration-storage-ux.md) 禁止的「房間畫布本機快取」是不同資料：
前者是明確規劃、可清除的秘密保存，後者是不該發生的內容外洩。**兩者不得互相援引。**

## 4. 獨立建房與初始化

本計畫開始串接前，18B §4.2.1 須已提供完整初始化狀態機與 owner 專用 API，`sceneId` 可為空。
本節負責瀏覽器操作與加密，沿用既有 ready／取消／退休契約，不把 metadata 建立成功當成內容保存成功。

1. 使用者從目前畫布選擇「開始加密共編」，登入後即可建立，**無 `sceneId` 不得停用入口**。
   清楚顯示「不會自動儲存為個人雲端場景」。
2. 建房前顯示房間加密範圍、完整連結含金鑰、以及遺失金鑰的結果。若來源為已存雲端場景，
   另提示原雲端副本仍未採 E2EE。
3. 呼叫 18B 建立 API 並保留穩定 roomId／建立 operationId；初始化內容走 owner 專用 API，
   不先一般 join，也不建立假的 scene。建立識別與各次保存操作識別分開。
4. 瀏覽器產生／保留房間秘密及 key-check，凍結一致的初始畫布資料供本次初始化使用。初始化期間保留本機
   內容，避免在快照切換時遺失新編輯；首版可暫停編輯並顯示進度。
5. 圖片以房間密文格式上傳與 finalize；初始快照同樣在瀏覽器加密。驗證所有被引用的初始附件可用，
   再完成初始化；房間未 ready 時不得讓其他人以空白 baseline 開始寫入。
6. 初始內容持久化確認後才顯示房間已就緒與可分享連結。失敗顯示具體未完成狀態，保留本機原稿與相同金鑰／
   建立 operationId 供重試；單次保存依 18B §4.4.1 保留相同密文與操作識別，
   查明成功／取消後才開始下一操作。**不以另存個人雲端作為恢復手段**。
7. 使用 18B 的狀態查詢、逾時／放棄與孤立密文清理 API；重載缺金鑰時提示提供完整連結，
   不重新產生金鑰覆寫同一房間。未保存內容依 18A 的原稿保留與未確認資料遺失邊界，
   不因有初始化意圖就宣稱伺服器握有整份畫布或能在瀏覽器離開後補完上傳。

從既有個人場景啟動共編的入口繼續支援，依其既有關聯規則運作。兩種入口共用 room 授權與密文儲存流程，
不複製第二套協作引擎。

**房間圖片不能直接沿用原個人場景的未加密物件 URL**；必須加密後獨立儲存。反向另存個人副本時，也不能讓
個人存檔依賴會隨房間清理的密文物件（這條與 18A §3 的附件生命週期要求一致）。

### 4.1 獨立房間在 18A 契約下的差異

18A 中所有以「來源 sceneId 是否存在」為條件的行為，在這裡必須對「沒有 scene」這個合法狀態也成立：

- 獨立房間不顯示「更新我的原場景」入口。
- 初始化與重進同樣適用 18A 的快取隔離與原稿恢復規則。
- 從獨立房間另存個人場景是**建立副本**：不改房間 owner、不新增 cascade 關係、不換金鑰、
  不解除房間 E2EE，也不切斷正在使用的房間。
- 刪除無關的個人場景不關閉獨立房間；舊的 scene-linked 房間保留已定義的 scene 退休關係。

## 5. 全產品加密告知

### 5.1 使用者必須理解的差異

| 模式／操作             | 實際保護                                       | 產品用語                       |
| ---------------------- | ---------------------------------------------- | ------------------------------ |
| 尚未存到雲端的個人畫布 | 位於本機；不保證瀏覽器儲存或匯出檔另有內容加密 | 尚未儲存至個人雲端             |
| 共編房間               | 快照與圖片以 E2EE 保存，服務端不持有房間秘密   | 共編內容端對端加密             |
| 個人雲端場景           | 場景與附件只有壓縮／編碼，服務端可還原         | 個人雲端存檔未採端對端加密     |
| 加密分享連結           | 分享副本加密，完整連結包含解密金鑰             | 加密分享；持有完整連結者可解密 |
| 公開發布               | 發布副本供他人公開閱讀                         | 公開內容                       |
| 一般本機匯出           | 檔案可直接讀取，不自動繼承房間 E2EE            | 匯出檔案未加密                 |

「未加密」在告知中指內容未做端對端加密，不表示沒有 HTTPS，也不表示自動公開。**禁止用「只有你能看」或
「所有資料皆加密」概括全產品**；可承諾的是房間內容的 E2EE，不包含帳號、角色、時間、大小等必要
metadata、[18B](18b-collaboration-authority-reset.md) §5.3 的允許清單信箱，或使用者自行建立的其他副本。

曾儲存到個人雲端的內容，之後開啟加密房間不會讓舊副本自動加密或消失。關閉、刪除或撤權也不能收回他人
已下載的內容；不宣稱可阻止成員另存。

### 5.2 常駐狀態與入口盤點

編輯器與「我的場景／我的房間」明確區分個人雲端副本與加密房間；保存進度不能只寫「已儲存」。房間可顯示
「加密快照已保存」，個人場景顯示「已儲存至個人雲端 · 非端對端加密」。未確認持久化時不得顯示已保存。

實作前盤點：工具列、主選單、雲端存檔對話框、快捷鍵、另存／複製、離開頁面提示、共編內的存檔入口、
可能的自動保存、公開發布、分享、匯出、列表、產品介紹與 onboarding。所有入口的狀態與用語必須一致；
可共用編輯器常駐標示，不要求每個按鈕重複展示說明，也不攔截快捷鍵或每次存檔。

### 5.3 低干擾原則

以不影響使用體驗、避免誤解為原則。透過儲存位置旁的簡短文字、常駐狀態標籤及既有存檔介面內的說明表達
保護範圍；**不新增每次存檔的確認對話框、同意勾選、強制閱讀或重複 toast**，也不增加日常存檔步驟。

建議短標示：「個人雲端 · 非端對端加密」。既有存檔介面可用一行說明：

> 個人雲端存檔不採端對端加密，不會自動公開。若希望雲端內容維持端對端加密，可只使用加密共編房間，
> 不另存個人雲端副本。

從房間另存時：「共編房間仍維持加密；另存的個人雲端副本不採端對端加密。」更完整的說明可放在可展開段落／
說明連結，**基本加密狀態不可只藏在 hover tooltip**。

- 若有首次介紹，採可略過的非阻擋式提示，不能取代日後可見的狀態標示，也不作為存檔授權條件。
- 個人模式不因增加說明而停用既有保存能力。
- 快取與副本的隔離是 18A 的存檔邊界，不是本計畫的提醒機制；**本計畫不得以「已經有告知」為由放寬它**。
- 告知是產品說明，不是阻止有權讀取明文者另存的安全邊界；既有 API 權限檢查仍須保留。

### 5.4 分享、發布、匯出與既有副本

- 完整加密邀請／分享連結的複製入口說明它包含金鑰；服務端授權與持有金鑰仍是兩個條件。
  若房間為限定模式（18B §5），一併說明「對方還需要以指定帳號登入」。
- 公開發布在既有發布介面明確說明公開範圍；若也會存個人雲端副本，同一介面交代兩個結果。
- 本機匯出提示檔案未加密，但不稱其為「上傳雲端」。採匯出對話框內說明，不額外跳出加密告警。
- 從已存個人雲端的場景開啟房間，說明既有副本仍存在；不自動刪除或承諾刪除可消除歷史備份與已下載副本。
- 所有支援語系保持相同含義；告知可由鍵盤與螢幕閱讀器操作，**不能只用鎖頭顏色傳達狀態**。
  網站文案僅宣稱共編／加密分享的 E2EE 範圍。
- 全程不自動上傳未加密縮圖、預覽或畫布內容到分析／日誌／錯誤報告。必要 metadata 範圍列入威脅模型。

## 6. 實作順序

1. 核對 18A／18B 的交接契約，盤點所有個人雲端寫入／衍生資料入口，固定畫面狀態與文案。
2. 串接 18B 的列表分頁 API，實作分頁 UI、同步中／故障與投影落後狀態。
3. 實作本機金鑰記憶與缺鑰體驗。
4. 接入獨立建房、初始化密文與附件、失敗重試及重進，沿用既有授權屏障。
5. 完成全產品一致的加密標示與低干擾存檔說明；**未完成之前不在 production 開放獨立共編入口**。
6. 完成測試與 production 驗收，再同步公開產品說明。

## 7. 驗收矩陣

標 `[L3]` 的項目需要已部署的 production 或真實多裝置操作（見 [18B §0.4](18b-collaboration-authority-reset.md)），
在 Neon 額度恢復前不得宣稱通過。

| 情境                                 | 必須證明的結果                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| 投影亂序、重送、刪除後晚到           | Neon 列表不倒退、不復活；列表暫時落後不授予權限                                             |
| Neon 故障 `[L3]`                     | 列表明確失敗或未完成，不以空資料冒充；房間本地撤權仍阻擋訊息                                |
| 列表包含獨立房間                     | 沒有 scene 的房間出現在列表；查詢未 inner join scene                                        |
| 我的房間／新裝置／錯鑰 `[L3]`        | 同瀏覽器有鑰可開；無鑰提示提供完整連結，錯鑰不修改存檔                                      |
| 登出與清除本機記錄                   | 本機房間秘密被清理，不殘留於其他 origin 可存取的位置                                        |
| 新畫布／含圖片的本機匯入直接建房     | 不要求 scene；不產生個人 scene、明文附件或縮圖；房間內容均走加密流程                        |
| 初始化任一步驟失敗、重送、重載       | 不產生重複房間、不丟本機原稿、不換錯金鑰；未 ready 不接受一般共編寫入，孤立附件可清理       |
| 離開／重進、DO 休眠                  | 有鑰恢復快照與圖片；缺鑰明確提示且不覆寫                                                    |
| 刪除個人副本／既有 scene-linked 場景 | 獨立房間不受副本刪除影響；舊關聯房間仍遵守退休契約                                          |
| 獨立房間的儲存入口                   | 沒有來源 scene 時不顯示「更新我的原場景」；18A 的儲存與快取規則在「沒有 sceneId」下同樣成立 |
| 日常存檔、重複存檔與快捷鍵           | 加密告知不新增確認彈窗、同意勾選或操作步驟；常駐狀態足以辨識儲存位置與加密範圍              |
| 另存個人雲端副本                     | 既有介面有簡短說明；房間仍加密，副本狀態標示準確                                            |
| 房間內容不外流為未加密衍生資料       | 沒有未加密預覽、縮圖、內容 telemetry 或金鑰上傳                                             |
